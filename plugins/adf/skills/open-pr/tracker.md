# The tracker task, once the pull request is ready

`/adf:open-pr` step 9, for work that came with a tracker task — a ClickUp task, a GitHub or GitLab
issue. A draft that stays one leaves the task where it is, with no review update.

- **The status:** move the task to the project's review status on your own — no yes needed, and no
  skill to load — as `docs/TRACKER-INTEGRATION.md` § Rules for agents says: the task's own status for
  the moment, through the project's tracker tool, read back, forward only; the status alone, in a
  call of its own. The task the developer handed this session is theirs to move, assigned to them or
  not. One line says so.
- **The review update** (`/adf:stakeholder-update review`): the business outcome, for the
  requester — what changes for them, the preview and what to test there — with the pull request link
  for reference, which relates the two. It posts on its own, and the report shows its text.
  Questions for the requester are a second message, a draft for the developer's yes; so is every
  message when § Stakeholder updates says *Updates post: on the developer's yes*.
- **Can't write** — no tracker tool, or only one built into the host app: the report opens with the
  status to set and the update's text to paste.

**In the report** (step 10): what you did on the task — the status, and the review update's text as
posted, with its link. A tracker you couldn't write to leads the report instead; a draft and its one
question come last.

Before the report, check:

- [ ] Once the pull request was ready, the task moved to the review status on its own, and the review update — the business outcome, the preview and what to test there, the pull request for reference — was posted and shown in the report
- [ ] Nothing that asks the requester for something was posted without the developer's explicit yes on the exact text; with no tracker tool that can write, the report opened with the status to set and the text to paste

## Rationalizations (do not accept these)

| Agent says... | Why it's wrong |
|---|---|
| "I'll draft the review update and let the developer post it" | An outcome report posts on its own, with the pull request link, and the report shows its text. Only a question for the requester waits for a yes. |
| "The pull request is still a draft, but the work is done — I'll move the task to review" | Review means a person can review it now. A draft moves nothing and posts nothing; the task moves once the pull request is ready. |
